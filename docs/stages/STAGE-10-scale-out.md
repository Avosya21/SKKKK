# Этап 10. Масштабирование

## Цель

Замена хранилищ, когда для этого появится измеримая причина. Этап открывается **только по факту**, а не по плану.

## Предусловия

Этапы 0–9 зелёные, система работает на реальных проектах не меньше нескольких недель, есть замеры.

## Триггеры

Не начинать этап, пока не выполнено хотя бы одно условие.

| Компонент | Триггер замены | Чем заменяем |
|---|---|---|
| sqlite-vec | Поиск по проекту дольше 1 секунды или больше ~500 тысяч чанков | Qdrant |
| Табличный граф | Нужны обходы глубже 2–3 шагов или запросы «найди путь между узлами» | Neo4j |
| SQLite | Устойчивые блокировки при записи, больше 20 активных пользователей | PostgreSQL |
| Одна GPU | Очередь транскрипций регулярно длиннее рабочего дня | Вторая карта либо отдельная машина под ASR |

## Полезные проекты на GitHub

Только когда сработал триггер из таблицы выше — не заранее.

| Проект | Что даёт | Как используем |
|---|---|---|
| [qdrant/qdrant](https://github.com/qdrant/qdrant) | Сама векторная БД — целевая замена sqlite-vec, Rust, один Docker-контейнер, HTTP+gRPC | Официальный `qdrant-client` для Python; коллекция с той же размерностью 1024 и тем же payload (`artifact_id`, `source_type`, `speaker`...), что уже в sqlite-vec — адаптер за интерфейсом сервиса, не переписывать вызывающий код |
| [qdrant/qdrant-client](https://github.com/qdrant/qdrant-client) | Официальный Python-клиент, `upsert`/`search`/фильтры по payload | Прямая замена SQL-запросов к `vec0` в п. 3 шагов («адаптер за существующим интерфейсом») |
| [neo4j/neo4j](https://github.com/neo4j/neo4j) | Целевая графовая СУБД, если понадобятся обходы глубже 2–3 шагов | Cypher вместо ручных JOIN по `entities`/`links`; переносить только когда обходы этих таблиц станут узким местом (см. триггеры) |
| [getzep/graphiti](https://github.com/getzep/graphiti) | Слой поверх Neo4j/FalkorDB с временными рёбрами и гибридным (граф + вектор) поиском, уже готовый паттерн миграции с эпизодами | Смотреть `examples/quickstart` как модель схемы при переносе таблиц `entities`/`links` в Neo4j, вместо проектирования схемы графа с нуля |
| [simonw/sqlite-utils](https://github.com/simonw/sqlite-utils) | Инструмент миграций и экспорта данных SQLite (`sqlite-utils migrate`, `sqlite-utils rows`) | Для п. 4 шагов — выгрузка данных из `app.db` в промежуточный JSON/CSV перед загрузкой в Qdrant/Neo4j, со счётчиком строк для сверки |

## Шаги (для каждой замены)

1. Зафиксировать текущие показатели: время поиска, размер индекса, длина очереди, время ответа чата. Без базовой линии «стало лучше» недоказуемо.
2. Поднять новое хранилище рядом со старым, не выключая старое.
3. Реализовать адаптер за существующим интерфейсом сервиса. Роутеры и UI не меняются.
4. Перенести данные скриптом, проверить пересчёт по числу записей и выборочно по содержимому.
5. Прогнать полный набор тестов против нового хранилища.
6. Сравнить показатели с базовой линией.
7. Переключить конфигурацией, старое хранилище оставить в режиме только для чтения на период наблюдения.

## Проверки

| Проверка | Ожидание |
|---|---|
| Перенос векторов | Число векторов совпадает, поиск по контрольным запросам даёт те же артефакты |
| Перенос графа | Число узлов и рёбер совпадает, типы связей сохранены |
| Перенос БД | Число строк по каждой таблице совпадает, приложение стартует без миграционных ошибок |
| Производительность | Замер лучше базовой линии, иначе замена не оправдана |
| Откат | Возврат к прежнему хранилищу конфигурацией работает |

## Тесты

Те же наборы тестов этапов 5, 6 и 7, запущенные против нового бэкенда — этим и проверяется, что адаптер эквивалентен:

```powershell
pytest app -m "not gpu" -q            # с переменной окружения, выбирающей бэкенд
```

Плюс `test_migration.py`:

- `test_vector_migration_preserves_count_and_top_hits`
- `test_graph_migration_preserves_nodes_and_edges`
- `test_rollback_to_previous_backend`

## Критерий готовности

- [ ] Замена сделана по факту триггера, а не «на будущее»
- [ ] Показатели улучшились относительно зафиксированной базовой линии
- [ ] Тесты прежних этапов зелёные на новом бэкенде
- [ ] Откат возможен и проверен

## Замечание

Каждое новое хранилище — это ещё одна служба Windows, которая может не подняться после перезагрузки, и ещё один источник расхождения данных. Для двадцати человек SQLite с векторным расширением закрывает задачу надолго. Соблазн поставить Neo4j «потому что граф» стоит проверять триггерами из таблицы выше.
