# Этап 9. Службы Windows и доступ по сети

## Цель

Система поднимается сама после перезагрузки и доступна коллегам по внутренней сети. До этого запуск был ручным.

## Предусловия

Этап 8 зелёный.

## Шаги

1. **Порядок запуска.** Зависимости: LM Studio и Ollama должны подняться до GPU-воркера. Воркер при старте ждёт доступности `/v1/models` и `/api/tags`, а не падает сразу.

2. **LM Studio как фоновая служба.** Проверить, что сервер поднимается без входа пользователя в графическую сессию. Если LM Studio требует активного сеанса — зафиксировать это как эксплуатационное требование: сервер работает под учётной записью с автоматическим входом, экран блокируется, сеанс не завершается. Это частая причина «после перезагрузки ничего не работает».

3. **Ollama** — служба, автозапуск, переменная окружения с ограничением GPU при необходимости.

4. **NSSM для нашего кода**:
   - `PrimaryAnalitics-API`: `venv\Scripts\python.exe -m app.app.main api --host 127.0.0.1 --port 1111`, рабочий каталог `D:\Primary_Analitics`, логи в `data\logs`;
   - `PrimaryAnalitics-GPU`: `venv\Scripts\python.exe -m app.app.main worker`;
   - автоперезапуск при падении с задержкой;
   - учётная запись, у которой есть доступ к GPU и к каталогу проекта.

5. **Nginx (по необходимости)**: reverse proxy на **1111** (не на 8000 — тот порт занимает MCP 1С), отдача статики, ограничение размера тела запроса не меньше лимита загрузки (иначе большие файлы будут отбиваться прокси), увеличенные таймауты для долгих загрузок. HTTPS — самоподписанный сертификат для внутренней сети.

6. **Сеть**: правило брандмауэра Windows для порта, фиксированный IP или запись в корпоративном DNS.

7. **Эксплуатационная инструкция** `docs/OPERATIONS.md`: запуск и остановка служб, где логи, как обновить приложение (остановить службы, обновить код, миграции, запустить), как снять бэкап, что проверять при жалобе «ничего не работает».

## Что появляется

Службы `PrimaryAnalitics-API`, `PrimaryAnalitics-GPU` в `services.msc`, документ `docs/OPERATIONS.md`.

## Проверки

| Проверка | Действие | Ожидание |
|---|---|---|
| Автозапуск | Перезагрузить машину, не входя в приложения | Портал доступен по сети |
| Порядок | Перезагрузка | Воркер дождался LM Studio, не упал |
| Доступ с другой машины | Открыть портал с ноутбука коллеги | Форма входа |
| Крупная загрузка через прокси | Файл 1.5 ГБ через Nginx | Загрузка проходит, не отбивается по размеру и таймауту |
| GPU из-под службы | Обработать аудио после перезагрузки | ASR отработал, служба видит карту |
| Падение службы | Снять процесс | NSSM перезапустил |
| Остановка на обновление | Остановить обе службы | Очередь не потеряна, после старта продолжилась |
| Логи | Проверить файлы после перезагрузки | Пишутся, не пустые |

Проверка «GPU из-под службы» обязательна: доступ к видеокарте из сервисного контекста Windows — известная точка отказа, и обнаружиться она должна здесь, а не в день демонстрации.

Скриншот `services.msc` с обоими сервисами (`PrimaryAnalitics-API`, `PrimaryAnalitics-GPU`) в статусе «Выполняется» после перезагрузки и скриншот портала, открытого с другой машины в сети, — минимальное визуальное подтверждение перед закрытием этапа.

## Тесты

Автотестами это не покрывается — проверяется сценарием на самой машине. Формализуется как чеклист приёмки развёртывания в `docs/OPERATIONS.md`:

1. Перезагрузка → портал доступен за N минут.
2. Загрузка тестового аудио → стенограмма готова, уведомление пришло.
3. `GET /health` → все зависимости в порядке.
4. `scripts/check_env.ps1` → PASS.
5. Остановка и запуск служб → очередь продолжается.

Дополнительно — тест `test_worker_waits_for_dependencies` (не `gpu`): при недоступных LM Studio и Ollama воркер повторяет попытки, а не завершается.

## Критерий готовности

- [ ] После перезагрузки всё поднимается без ручных действий
- [ ] ASR работает из-под службы
- [ ] Портал доступен коллегам по сети
- [ ] Большие файлы проходят через прокси
- [ ] `docs/OPERATIONS.md` написан и проверен по шагам

## Типичные отказы

| Симптом | Причина | Что делать |
|---|---|---|
| После перезагрузки нет LM Studio | Требуется графический сеанс | Автовход в учётную запись, блокировка экрана вместо выхода |
| Служба не видит GPU | Учётная запись без доступа | Запускать от пользователя, а не от Local System |
| Большие файлы отбиваются | Лимит тела в Nginx | Увеличить лимит и таймауты |
| Воркер падает при старте | Зависимости ещё не поднялись | Ожидание с повторами |
