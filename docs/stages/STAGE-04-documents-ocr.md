# Этап 4. Документы, заметки, изображения

## Цель

Все остальные типы артефактов приводятся к тому же результату, что и аудио: чистый структурированный текст в `parsed/`. Дальше конвейер их не различает.

## Предусловия

Этап 3 зелёный (LLM-провайдер работает: lmstudio или cursor).

## Шаги

1. **PDF** `services/extract.py`:
   - текстовый слой через PyMuPDF, с сохранением заголовков, списков, таблиц;
   - определение «скана»: если на страницу приходится меньше порога символов, страница уходит в OCR;
   - смешанный PDF обрабатывается постранично: где есть текст — берём текст, где нет — OCR;
   - результат в `parsed/documents/{id}_raw.txt`.

   - таблицы — `page.find_tables()` (PyMuPDF): markdown-таблица на своём месте по вертикали, текст страницы без области таблицы (без дублей). *(2026-09-25)*

2. **DOCX** (`services/docx_extract.py`): обход тела документа по порядку — заголовки (`#` по стилю или «3.2. Текст»), абзацы, списки, **таблицы на своих местах** (раньше все таблицы шли в конец файла), вложенные таблицы, надписи, колонтитулы. Объединение по горизонтали — одно значение, по вертикали — повтор. `.doc/.odt/.rtf` — через LibreOffice → DOCX. *(2026-09-25)*

2а. **Excel / CSV** (`services/xlsx_extract.py`, `file_type=xlsx`): `.xlsx/.xlsm` — openpyxl (значения формул), `.xls/.ods` — через LibreOffice, `.csv/.tsv` — `csv.Sniffer`. Каждый видимый лист — `## Лист: имя`, внутри таблицы по блокам (разрыв — пустая строка), надпись над таблицей — подпись, двухуровневая шапка «верх / низ», даты `ДД.ММ.ГГГГ`, числа с разрядами по формату ячейки. Лимит 5000 строк и 60 столбцов на лист с явной пометкой. LLM-нормализация для Excel не вызывается. *(2026-09-25)*

Общий формат таблицы для всех источников — `services/table_md.py`: строка `Таблица N: подпись` + GFM (`|` в ячейке экранирован, переносы — «; »).

3. **Изображения**: Tesseract `rus+eng`; при слабом OCR — **vision через LLM** (`services/image_extract.py`: lmstudio multimodal или Cursor `SDKImage`).

4. **TXT и ручной ввод**: нормализация пробелов и пустых строк, без смысловой правки.

5. **Нормализация через LLM** (модули 2.2 и 3 плана): промпт `docs/prompts/normalize_document.md`. Длинные документы — по частям: по заголовкам, а без заголовков — по абзацам до 8000 символов (раньше документ без `#` уходил одним запросом и обрезался по `max_tokens`). **Таблицы в LLM не уходят**: метка `[[ТАБЛИЦА_N]]`, после ответа — таблица дословно; потерянная моделью метка дописывается. Часть, которую модель «ужала» до < 60 %, заменяется лёгкой нормализацией (`normalize.shrunk` в журнале). Итог `{id}_clean.txt`, статус `text_extracted`.

6. **Защита от «улучшений»**: нормализация не должна терять числа, даты, суммы и пункты. Проверяется тестом.

## Что появляется на диске

```
data\projects\{id}\parsed\documents\art_..._raw.txt
data\projects\{id}\parsed\documents\art_..._clean.txt
data\projects\{id}\parsed\notes\art_..._clean.txt
```

## Полезные проекты на GitHub

Стек уже выбран в [PLAN.md](../PLAN.md) (pymupdf / python-docx / Tesseract), ниже — проекты для конкретных сложных мест (детект «скан vs текст», таблицы).

| Проект | Что даёт | Как используем |
|---|---|---|
| [Unstructured-IO/unstructured](https://github.com/Unstructured-IO/unstructured) | Автоопределение типа файла и стратегии (`hi_res`/`ocr_only`/`fast`), уже готовая логика «мало текста на странице → OCR» | Референс для порога и логики переключения в `services/extract.py`, пункт 1 «шагов» этого этапа. Не тащить всю библиотеку как зависимость — она тяжёлая (`unstructured[all-docs]` тянет torch); достаточно pymupdf + собственный порог по числу символов |
| [pymupdf/PyMuPDF](https://github.com/pymupdf/PyMuPDF) | Сам движок для текстового слоя PDF, уже выбран | Смотреть `page.get_text("dict")` для сохранения структуры (заголовки по размеру шрифта) вместо плоского текста |
| [python-openxml/python-docx](https://github.com/python-openxml/python-docx) | Официальный пакет для DOCX, уже выбран | `document.tables` → ручная сборка markdown-таблицы для пункта 2 шагов |
| [tesseract-ocr/tesseract](https://github.com/tesseract-ocr/tesseract) | Сам OCR-движок, уже выбран (`rus+eng`) | Смотреть `--psm`/`--oem` режимы, если распознавание таблиц или колонтитулов на скан-PDF будет плохим |
| [JaidedAI/EasyOCR](https://github.com/JaidedAI/EasyOCR) | Альтернативный OCR на PyTorch, часто точнее Tesseract на шумных фото | Запасной вариант **только** если Tesseract даст мусор на реальных скриншотах пользователей — тогда сравнить на тех же образцах из `app/app/tests/fixtures/`, не менять движок по умолчанию без такого сравнения |

## Проверки

Набор образцов в `app/app/tests/fixtures/`: текстовый PDF, скан-PDF на русском, PDF с таблицей, DOCX с заголовками, скриншот переписки, txt-заметка.

Открыть страницу проекта в браузере (`http://127.0.0.1:1111/projects/{id}`) после загрузки каждого образца, скриншот карточки файла со статусом `text_extracted` и, если в UI уже есть предпросмотр `_clean.txt`, скриншот самого текста — сверить глазами, что таблица и числа не потерялись, а не только через `assert` в тесте.

| Проверка | Действие | Ожидание |
|---|---|---|
| Текстовый PDF | Загрузить | `_raw.txt` содержит текст, OCR не запускался |
| Скан-PDF | Загрузить | Текст распознан по-русски, не мусор |
| Смешанный PDF | Загрузить | Текстовые страницы не прогонялись через OCR |
| Таблица | PDF/DOCX/XLSX/CSV с таблицей | В `_clean.txt` таблица читаема (markdown) и стоит под своим разделом |
| Excel | `.xlsx` со сметой (объединённая шапка, итог) | Шапка «Стоимость / без НДС», итог в своей строке, скрытые листы не попали |
| Неподдерживаемый формат | `.zip` | Отказ при загрузке (415) с понятным текстом |
| Скриншот | PNG с русским текстом | Текст извлечён |
| Сохранность фактов | Документ с суммами и датами | Все числа и даты присутствуют в `_clean.txt` |
| Колонтитулы | PDF с номерами страниц | Номера страниц вычищены |
| Пустой документ | PDF без текста и без изображений | Статус `error` с внятным сообщением, не «зависание» |

## Критерий готовности

- [ ] Пять типов входа дают `_clean.txt`
- [ ] Скан распознаётся по-русски
- [ ] Числа и даты не теряются при нормализации
- [ ] Длинный документ не обрезается по контексту
- [ ] Таблицы DOCX/XLSX/CSV/PDF — markdown на своих местах, числа таблиц из `_raw` все есть в `_clean` (`scripts/reprocess_documents.py`, столбец «нет_чисел» = 0)
- [ ] Тесты `test_documents.py` и `test_normalization.py` зелёные

## Типичные отказы

| Симптом | Причина | Что делать |
|---|---|---|
| OCR даёт латиницу вместо кириллицы | Не указан язык | `lang="rus+eng"` |
| Таблицы превращаются в кашу | Извлечение без учёта колонок | PDF — `find_tables` (есть); таблица без рамок не находится — остаётся текстом страницы |
| `.doc`/`.xls` в ошибке «нужен LibreOffice» | Нет `soffice` | `tools/libreoffice` в проекте или `SOFFICE_PATH` |
| Gemma «дописала» раздел | Свободный промпт | Ужесточить: запрет добавлять факты |
| Очень медленный OCR | Большой скан в высоком разрешении | Ограничить DPI, распараллелить по страницам на CPU |
