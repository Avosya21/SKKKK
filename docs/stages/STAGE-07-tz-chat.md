# Этап 7. Актуальное ТЗ и чат по проекту

## Цель

Система выдаёт то, ради чего затевалась: единый живой документ проекта и ответы на вопросы со ссылками на первоисточники.

## Предусловия

Этап 6 зелёный.

## Шаги

1. **Пересборка ТЗ** (модуль 9):
   - триггеры: кнопка администратора, накопление N новых `graph_seeded` (по умолчанию 3), ручное разрешение конфликта;
   - вход: активные сущности, разрешённые противоречия с причинами, заметки, привязанные к ключевым узлам, текущая версия ТЗ;
   - промпт `docs/prompts/rebuild_tz.md`;
   - если материала больше, чем помещается в контекст: сборка по разделам, раздел за разделом, затем сшивка;
   - предыдущая версия уезжает в `project_state/versions/current_tz_{timestamp}.md`, новая становится `current_tz.md`;
   - запись в `changelog` с перечнем артефактов и кратким описанием изменений;
   - задача идёт в очередь с `phase=llm` и ждёт, если идёт транскрипция.

2. **Версии** (модуль 12): список версий, сравнение двух (визуальный diff по разделам), восстановление любой версии как текущей — с новой записью в changelog, без затирания истории.

3. **Ручная правка ТЗ администратором**: правка сохраняется как новая версия с пометкой «правка вручную».

4. **Чат** (модуль 11):
   - эмбеддинг вопроса через Ollama (CPU);
   - семантический поиск по чанкам проекта;
   - извлечение ключевых сущностей вопроса и подтягивание соседних узлов графа;
   - промпт `docs/prompts/rag_chat.md`;
   - ответ обязан содержать источники: `artifact_id` и имя файла;
   - если контекст пуст — «в материалах проекта ответа нет», без сочинительства;
   - ссылка из ответа открывает карточку артефакта.

5. **Очередь чата**: во время фазы ASR запрос ждёт, интерфейс честно пишет «идёт транскрипция, ответ будет через…».

## Что появляется на диске

```
data\projects\{id}\project_state\current_tz.md
data\projects\{id}\project_state\versions\current_tz_2026-08-20_1000.md
```

## Полезные проекты на GitHub

RAG идёт по своей схеме (Ollama-эмбеддинг + sqlite-vec + соседи графа → Gemma, без Qdrant/Neo4j на этом этапе), но паттерны сборки длинного документа по частям и RAG-по-графу уже обкатаны в открытых проектах.

| Проект | Что даёт | Как используем |
|---|---|---|
| Свой прототип: `asr/summarize_call.py` + `docs/prompts/call_summary.md` | Уже реализованный на этом же проекте map/reduce: длинный текст режется на части, по каждой — черновая выжимка, затем один запрос сшивает всё в итог, без потери контекста | Прямой шаблон для «сборка ТЗ по разделам» из п. 1 шагов: тот же приём (map по частям текста → reduce в один документ) вместо изобретения нового алгоритма для `rebuild_tz.md` |
| [HKUDS/LightRAG](https://github.com/HKUDS/LightRAG) | RAG с двухуровневым индексом (граф сущностей + векторы), режимы `local`/`global`/`hybrid` поиска по графу | Референс для логики чата п. 4: как сочетать «похожие чанки» и «соседи сущности в графе» в одном запросе к LLM, не два независимых промпта |
| [getzep/graphiti](https://github.com/getzep/graphiti) | Граф знаний с временными рёбрами (когда факт стал верен/устарел), поверх Neo4j/FalkorDB | Не для внедрения сейчас (у нас Neo4j — этап 10), но полезная модель для `changelog`/версий ТЗ: как хранить «этот факт был верен до даты X, потом заменён» |
| [microsoft/graphrag](https://github.com/microsoft/graphrag) | Эталонная (хоть и тяжёлая) реализация построения сообществ графа и суммаризации по кластерам сущностей | Идея для будущего раздела ТЗ «сводка по теме» — группировать сущности в кластеры перед сборкой раздела, если один плоский список станет нечитаемым |

## Проверки

Сценарий из этапа 6 (бюджет 3 млн в PDF, 4 млн на созвоне, конфликт разрешён администратором в пользу созвона).

Открыть `http://127.0.0.1:1111/projects/{id}/tz` и `.../chat`, скриншот собранного ТЗ (все разделы плюс раздел «Открытые вопросы» с неразрешённым конфликтом) и скриншот диалога чата с вопросом «какой у нас бюджет» — в ответе должна быть видна ссылка/пометка источника, а не просто голый текст.

| Проверка | Действие | Ожидание |
|---|---|---|
| Первая сборка | Нажать «Пересобрать ТЗ» | `current_tz.md` со всеми семью разделами |
| Источники | Открыть раздел решений | Указаны artifact_id |
| Разрешённый конфликт | Проверить бюджет в ТЗ | 4 млн, в истории решений отражено, что 3 млн отменены и почему |
| Неразрешённый конфликт | Оставить конфликт открытым, пересобрать | Пункт в разделе «Открытые вопросы», а не молчаливый выбор |
| Версии | Пересобрать дважды | Старая версия в `versions/`, changelog пополнился |
| Diff | Сравнить две версии | Видны добавленные и изменённые разделы |
| Восстановление | Вернуть первую версию | Стала текущей, история не потеряна |
| Чат по факту | «Какой у нас бюджет?» | 4 млн со ссылкой на созвон |
| Чат по причине | «Почему увеличили бюджет?» | Ответ опирается на разрешение конфликта |
| Чат без данных | «Кто поставщик серверов?» (не обсуждалось) | «В материалах проекта ответа нет» |
| Изоляция | Вопрос про чужой проект | Данные другого проекта не попадают в ответ |
| Очередь | Задать вопрос во время ASR | Ждёт, VRAM не растёт |
| Автотриггер | Загрузить три артефакта | Пересборка запустилась сама один раз, не трижды |

## Критерий готовности

- [ ] ТЗ собирается со всеми разделами и ссылками на источники
- [ ] Неразрешённые противоречия видны как открытые вопросы, а не решаются молча
- [ ] Версии архивируются, diff и восстановление работают
- [ ] Чат отвечает с источниками и честно отказывается без данных
- [ ] Изоляция проектов соблюдена в поиске, графе и чате
- [ ] Пересборка не запускается на каждый файл
- [ ] Тесты `test_tz.py` и `test_chat.py` зелёные

## Типичные отказы

| Симптом | Причина | Что делать |
|---|---|---|
| ТЗ теряет разделы | Не хватило контекста | Сборка по разделам |
| В ТЗ попали отменённые решения | Фильтр активности не применён | Проверить `is_active` |
| Чат выдумывает | Слабое ограничение в промпте | Явный запрет и обязательные источники |
| Ответы без ссылок | Модель игнорирует требование | Проверять наличие источников программно, при отсутствии — повтор |
| Пересборка на каждый файл | Триггер неверен | Считать накопление, а не событие загрузки |
