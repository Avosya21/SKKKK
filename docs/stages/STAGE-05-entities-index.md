# Этап 5. Сущности и семантический индекс

## Цель

Из текста получаются структурированные сущности (решения, задачи, факты, участники) и векторный индекс, по которому работает поиск и последующий чат.

## Предусловия

Этап 4 зелёный. Ollama `bge-m3` отвечает и не занимает VRAM.

## Шаги

1. **Извлечение сущностей** (модуль 4): промпт `docs/prompts/extract_entities.md`, ответ строго JSON.
   - парсинг с валидацией по Pydantic-схеме; невалидный JSON — один повтор с указанием ошибки, затем `error`;
   - длинный текст обрабатывается частями, результаты объединяются с дедупликацией;
   - файл `structured/{id}_entities.json`;
   - строки в `entities` с `needs_review = true` и `confidence`;
   - статус `entities_extracted`.

2. **Ревью сущностей в UI**: на карточке артефакта список извлечённого с кнопками «принять», «править», «отбросить». Принятая сущность теряет `needs_review`. Отброшенная получает `is_active = false`.

3. **Чанкинг** `services/chunking.py`: 512 токенов, перекрытие 128, границы по предложениям. Для стенограмм — по репликам, с сохранением спикера. Запись в `chunks`.

4. **Эмбеддинги**: Ollama `bge-m3`, обязательно `options.num_gpu = 0`, пакетами, с ретраем. Размерность строго 1024 — проверять, а не предполагать.

5. **Хранение векторов**: sqlite-vec, payload по плану (artifact_id, source_type, timestamp, author, chunk_index, speaker, priority_weight). Статус `indexed`.

6. **Поиск** `GET /projects/{id}/search?q=`: топ-N чанков с оценкой и ссылкой на артефакт. Пока без LLM — сырой семантический поиск, его качество проверяется отдельно от качества ответов чата.

7. **Калибровка порога схожести**: скрипт `scripts/calibrate_threshold.py` считает распределение сходства на реальных парах проекта и предлагает значение для `projects.settings_json`. Значение 0.82 — стартовое предположение, а не константа.

## Что появляется на диске

```
data\projects\{id}\structured\art_..._entities.json
data\app.db                       (таблицы chunks + векторный индекс)
```

## Полезные проекты на GitHub

Извлечение сущностей идёт через Gemma (JSON-промпт, уже решение проекта), но для чанкинга/индекса и как запасной вариант NER без LLM полезны:

| Проект | Что даёт | Как используем |
|---|---|---|
| [asg017/sqlite-vec](https://github.com/asg017/sqlite-vec) | Сама векторная СУБД-расширение, уже выбрана в стеке | Официальные примеры `vec0` виртуальных таблиц и `distance_metric=cosine` — прямой референс для `services/chunking.py`/хранилища векторов, включая `serialize_float32` для формата BLOB |
| [natasha/natasha](https://github.com/natasha/natasha) | CPU-библиотека для русского NLP: сегментация предложений, морфология, NER, извлечение имён/дат/денег без LLM | Кандидат для дешёвой предобработки перед вызовом Gemma (например, разбиение на предложения для чанкинга по границам, п. 3 шагов) или как офлайн-сверка «не потеряла ли Gemma очевидное имя/дату» |
| [urchade/GLiNER](https://github.com/urchade/GLiNER) (русская дообученная версия — [fulstock/GLiNER-ru](https://github.com/fulstock/GLiNER-ru)) | Zero-shot NER на CPU/GPU без LLM, 29 типов сущностей на русском (NEREL) | Референс, если разметка `entities` от Gemma окажется нестабильной по типам — можно сверять `entity_type` независимой моделью перед `needs_review=false` |

## Проверки

Открыть `http://127.0.0.1:1111/projects/{id}` после обработки артефакта, скриншот карточки с извлечёнными сущностями (список с пометкой «на проверке») и отдельно скриншот страницы поиска с результатом семантического запроса — сверить, что в топе действительно релевантный чанк, а не первый попавшийся.

| Проверка | Действие | Ожидание |
|---|---|---|
| JSON валиден | Обработать стенограмму | Файл сущностей соответствует схеме |
| Повтор при ошибке | Смоделировать невалидный ответ LLM | Один повтор, затем понятная ошибка |
| Ревью | Открыть карточку артефакта | Видны сущности с пометкой «на проверке» |
| Отбрасывание | Отбросить ложную задачу | `is_active = false`, в поиске и ТЗ не участвует |
| Чанки | Проверить границы | Нет обрыва посреди предложения, перекрытие соблюдено |
| Размерность | Проверить вектор | Ровно 1024 |
| VRAM | `nvidia-smi` во время индексации | Прироста нет, Ollama на CPU |
| Поиск | Запрос «бюджет» на проекте с обсуждением бюджета | В топе релевантные чанки из нужного артефакта |
| Поиск по смыслу | Запрос «сколько денег» без слова «бюджет» | Тот же чанк находится |
| Повторная обработка | Обработать артефакт дважды | Чанки и векторы не дублируются |

## Критерий готовности

- [ ] Сущности извлекаются в валидный JSON и попадают в БД с пометкой на проверку
- [ ] Ревью в UI работает, отброшенное не участвует дальше
- [ ] Вектор ровно 1024, индексация не занимает VRAM
- [ ] Поиск находит по смыслу, а не только по словам
- [ ] Поиск строго в пределах проекта
- [ ] Повторная обработка не плодит дубли

## Типичные отказы

| Симптом | Причина | Что делать |
|---|---|---|
| LLM обрамляет JSON в markdown | Особенность модели | Снимать ограждение перед парсингом, в промпте требовать чистый JSON |
| Придуманные сроки и исполнители | Модель заполняет пустоты | В промпте — только `null`; всё под ревью человеком |
| Медленная индексация | Эмбеддинги по одному | Пакетные запросы |
| Ollama ушёл на GPU | Не передан `num_gpu` | Передавать в каждом запросе |
