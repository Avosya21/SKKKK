## 1. С чего начали (постановка)

В портал добавили новый инструмент — подтягивание данных из Jira: личный токен пользователя,
выбор проектов Jira на главной странице и загрузка задач с вложениями как обычных материалов
проекта (`services/jira_client.py`, `services/jira_import.py`, `routers/jira.py`; план —
`docs/plans/JIRA-INTEGRATION-PLAN.md`).

Задача: **убедиться, что всё из Jira подтянулось полнообъёмно и правильно разложено в память
проекта** — чтобы локальный агент мог отвечать на любой вопрос по проекту; зафиксировать это
e2e-тестами и автоматической проверкой.

Критичные ограничения:

- машина тянет **одну модель** (`swift-qwen3.8-27b` в RAM); `lms load` через портал = дубль модели →
  нехватка RAM;
- всё тестирование — **без вызовов модели проекта**: скриптами, venv'ом и pytest (portal
  поднимался/падал не по нашей вине);
- воркер портала забирает queued job'ы из общей очереди → в неё **не ставили** новые
  `process_artifact`, обработку делали in-process;
- портал работает только на локальном хосте, перезапуск — опционально и рискован.

## 2. Что нашли (изучение проекта и живых данных)

По проекту:

- конвейер подтяжки: задачи Jira → md-документы («Jira КЛЮЧ-N — …» с описанием, комментариями
  и списком вложений), вложения → файлы через штатную регистрацию материалов
  (`create_artifact_record` + очередь `jobs`) → обычный разбор (векторы, граф, сущности);
- обновление — по кнопке и по расписанию (`JIRA_SYNC_MINUTES`, по умолчанию 30 мин); доступ к

## 3. Зачем делали

1. **Доверие к данным**: картина по проекту строится из Jira, и каждый ответ агента опирается на

   гонять перед каждым релизом.

### 9.2. Как теперь проверяется полнота

- Кнопка «Проверить полноту» на странице проекта и `GET /projects/{id}/jira/check` (то же делает `scripts/check_jira_sync.py`):
  заново читает каждую задачу из Jira, строит документ и сравнивает с сохранённым **буква в букву**; сверяет число задач,
  вложений и их размеры, состояние разбора каждого материала; перечисляет поля, которые намеренно не выводятся (служебные).
- Формат документа версионируется (`jira_render.FORMAT_VERSION`): при смене вида все задачи перечитываются сами.
