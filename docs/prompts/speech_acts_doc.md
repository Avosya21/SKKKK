# Промпт: акты единиц документа (документы в памяти решений)

Версия `speech_acts_doc-v2` (v2: контекст не размечается, ответ одной строкой — длинные ответы обрывались на строках плана). Документ размечается как созвон, но вместо реплик — единицы: абзац, пункт списка, строка таблицы (`P<n>`). План — `docs/plans/DOCUMENT-MEMORY-PLAN.md`. Код проверяет метку, вид акта и дословность цитаты; сторону, дату и утверждение документа берёт из паспорта, не из ответа модели.

```
Ты размечаешь документ проекта внедрения: что каждый его пункт делает для решений проекта. Первая строка — что это за документ.
Строки с «>» — целевые единицы, их размечай; строки с «·» — только контекст до них. Строка «§ …» — раздел документа.
У строки таблицы в квадратных скобках — шапка таблицы: по ней понятно, что значит каждое значение строки.

Для каждой целевой единицы, которая что-то значит для решений, требований, работ или их статуса, верни объект. Пропускай: оглавление,
номера страниц, реквизиты, служебные подписи, общие слова, определения терминов, а также описание того, как всё устроено сейчас
(«как есть», AS-IS), если в нём нет требования, ограничения или решения на будущее.

Виды акта (act):
- documented — пункт фиксирует требование, решение, условие, обязательство, состав или границы работ, срок, цену, ответственного,
  выбранный вариант («Система должна…», «Принят вариант B», «Срок — до 20.04.2026», «Исполнитель обеспечивает…», строка плана
  «этап — задача — срок»);
- proposed — пункт выносит вариант на рассмотрение, а не фиксирует его («предлагается», «рекомендуем», «на согласование»,
  несколько вариантов без выбора);
- agreed — пункт сообщает, что нечто согласовано или утверждено («согласовано с заказчиком», «утверждено протоколом», статус «Согласовано»);
- rejected — пункт отклоняет вариант («вариант A не принят», «от … отказались», статус «Отклонено»);
- done — сделано (статус «Готово», «Выполнено», «внедрено», «загружено», «подписан»);
- deferred — отложено или вынесено за рамки («перенесено на этап 2», «вне рамок текущего этапа», статус «Отложено»);
- cancelled — отменено, исключено, «не актуально»;
- blocked — препятствие («ждём заказчика», «нет доступа», «не предоставлены данные»);
- asked — открытый вопрос («не определено», «требует уточнения», «непонятно, как…», вопрос в примечании);
- info — факт или ограничение, которое влияет на решения (объёмы, число пользователей, сроки поставщика), без требования.

Правила:
- Строка таблицы задач со статусом может нести два акта: documented (сама задача или результат) и done / deferred / blocked по статусу
  («В работе» — только documented). Цитата у каждого своя: задача — текст задачи, статус — слово статуса вместе с задачей, если оно короткое.
- «[примечание: …]» в ячейке — отдельный акт по смыслу примечания (чаще blocked, asked или info), цитата — из текста примечания.
- «Рисунок …:» со схемой процесса: размечай шаги, роли и ветвления, если они задают, как должно работать (documented), иначе пропусти.
- Не больше трёх актов на единицу. Длинный абзац с несколькими требованиями — несколько documented с разными цитатами.

Поля объекта:
- unit — метка целевой единицы (например P12);
- act — один из видов выше;
- quote — ДОСЛОВНАЯ цитата из текста этой единицы (предложение или его часть, без правок);
- about — короткая фраза: о чём именно (предмет решения, не пересказ пункта), до 120 знаков.

Размечай только единицы, перечисленные в строке «Размечай ТОЛЬКО единицы»; строки «·» (контекст) в ответе не упоминай.
Ответ — только JSON одной строкой, без отступов, пояснений и markdown: {"acts": [{"unit": "P12", "act": "documented", "quote": "...", "about": "..."}]}.
Нет ни одного акта — {"acts": []}.
```
