# Промпт: актуальность пунктов одной темы (дубли, заменённое, выполненное) — v2 с похожими пунктами из других тем

Модель читает пункты одной темы по хронологии и говорит про каждый, актуален ли он (docs/plans/REQUIREMENTS-PLAN.md,
этапы 6–7). Код проверяет ответ: заменивший позже по дате записи (обе даты известны), подтверждается своим источником,
не слабее по весу (правила Р1); подтверждённое человеком — по решению А6. Версия: `review_relevance` v2 (2026-09-28).
v2: после темы идут похожие пункты из других тем — модель могла развести способы одной потребности по разным темам
(замер «ПИЛОТА»: приложение в Битрикс24 и нормализация в 1С). v1 оставлен файлом.

```
Ты проверяешь актуальность пунктов ОДНОЙ темы проекта внедрения 1С. Пункты даны по хронологии: раньше — выше.
У каждого: номер E<n>, дата записи материала (или «дата неизвестна»), вид (решение / задача / вопрос), вес источника,
кто сказал и кто утвердил, текст и цитата из источника. Опирайся ТОЛЬКО на тексты и цитаты. Ничего не додумывай.

Для КАЖДОГО пункта верни state:
- "current" — в силе: позже от него не отказались.
- "superseded" — позже выбрали ДРУГОЙ путь или явно отказались: пункт больше не актуален. by — пункт, который его заменил
  (он должен быть ПОЗЖЕ). Пример: раньше «сделать приложение в Битрикс24 для ввода характеристик», позже «характеристики
  ведём в 1С через нормализацию справочника» — первое superseded, by — второе.
- "duplicate" — та же мысль, что и в другом пункте темы, другими словами (повтор на другой встрече). by — пункт, который
  остаётся основным (обычно самый ранний с этой мыслью).
- "done" — по более поздним пунктам видно, что это уже сделано. by — пункт, где это видно.
- "unclear" — не уверен. Лучше "unclear", чем ошибка.

После пунктов темы может идти блок «Похожие пункты из других тем». Они только кандидаты в by (заменивший или основной):
пункт темы может быть заменён или повторён пунктом оттуда. Сами пункты этого блока не оценивай и в items не включай.
Уточнение или дополнение (позже конкретизировали, не отменяя) — это "current", а не "superseded".
Вопрос или предложение без согласия не заменяет утверждённое решение.
quote — короткая дословная цитата из пункта by, на которой основан вывод (для current — пусто).
reason — одна короткая фраза по-русски. confidence — от 0 до 1.

Ответь ТОЛЬКО валидным JSON без markdown-ограждений:
{"items": [{"id": "E12", "state": "superseded", "by": "E20", "quote": "...", "reason": "...", "confidence": 0.9}]}
```
