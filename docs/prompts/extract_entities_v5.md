## Контекст

Перед текстом могут идти блоки «Карточка проекта», «Оглавление созвона», «Темы проекта» и «Конец предыдущей части».

Из контекста НИЧЕГО не извлекай — только из основного текста. Реплики из «Конца предыдущей части» уже разобраны.

## Виды пунктов

Каждый пункт — одного вида (поле kind):
- decisions, kind="requirement" — как должна работать система: поле, форма, обмен, отчёт, права, печатная форма.
- decisions, kind="project" — решение по проекту: подход, архитектура, мастер-система, этапы, разделение ролей.
- tasks, kind="work" — работа по системе: разработать, настроить, доработать, нормализовать, перенести.
- tasks, kind="org" — организационное: назначить созвон, прислать файл, посчитать часы, согласовать смету, пригласить человека.
- open_questions — не решено: вопрос без ответа или варианты, между которыми ещё не выбрали
  («вариант А — …, вариант Б — …, ждём выбора заказчика»). Варианты — в options. Это НЕ decision.
Предложение без согласия («может, сделаем…», «предлагаю…») — не decision: это open_question или ничего.

## Формулировка — понятна без созвона

Каждый text / description — самостоятельная фраза, понятная человеку, который созвон не слышал:
ОБЪЕКТ (документ, справочник, система, роль) + ЧТО делаем + УСЛОВИЕ или ЗАЧЕМ.
- Плохо: «Добавляются два доп-реквизита в строку табличной части». Хорошо: «В строку табличной части заказа клиента
  в 1С добавить доп-реквизиты „Длина листа“ и „Количество листов“ для номенклатуры профнастила».
- Без «это», «там», «он», «как обсуждали», «данный» — назови объект словами.
- Объект и систему бери из реплик и контекста; не придумывай то, чего нет ни там, ни там.
- object — объект коротко («заказ клиента», «справочник номенклатуры», «коннектор 1С–Битрикс24»).
- topic — тема проекта: потребность или объект («ввод характеристик номенклатуры»), а НЕ способ решения. Если в блоке
  «Темы проекта» есть подходящая — возьми её название дословно; иначе предложи короткое новое.

## Задачи и сроки

- Одно обязательство — одна task: состав одного результата пиши в description той же task.
- Отдельная task — только самостоятельное действие со своим исполнителем и/или сроком.
- Срок, дату, дедлайн («до конца недели», «к пятнице», «к 15.03», «в течение часа») пиши в deadline дословно, как сказано.
- deadline_at — тот же срок точной датой для календаря: «ГГГГ-ММ-ДД» или, если названо время, «ГГГГ-ММ-ДДTЧЧ:ММ».
  Считай от timestamp в начале запроса (дата и время созвона или документа): «до пятницы» — ближайшая пятница после
  timestamp; «на следующей неделе» — понедельник следующей недели; «в течение часа» — timestamp плюс час; «до конца дня» —
  этот день, 18:00; «к 15.03» без года — год из timestamp. Диапазон («в четверг-пятницу») — конечная дата. Названо только
  время («в 15:00») — дата созвона. Нет точного срока, нет timestamp при относительном сроке или не уверен — deadline_at: null;
  дату не выдумывай.
- Количество, объём и длительность («до 10 курсов», «до 4 встреч по 1 часу», «не более 5 человек») — не срок: deadline: null.
- Не путай длительность этапа («этап 1 — 4–6 недель», оценка трудозатрат) и очередность этапов («перед этапом 2») с дедлайном.
- assignee — имя человека, команды или роли из текста; не SPEAKER_00, если есть реальное имя. Если исполнитель — говорящий,
  чьё имя в стенограмме указано, бери имя из реплики; метку speaker_N пиши, только когда имени нет нигде.
- status: open | done | cancelled | unknown — только если явно следует из текста.

## Реплики и согласие (для созвонов)

- Стенограмма — пронумерованные реплики «T<номер> [таймкод] Имя: текст». decision/task/fact/open_question — только из
  реплик основного текста; в turns — номера реплик, где это прозвучало (например [12, 13]).
- decided_by — кто утвердил решение или явно согласился («да, так и делаем», «согласен», «принято»), с номером ЕГО реплики:
  [{"name": "Павел Пилот", "turn": 14}]. Имя — ровно как в реплике. Кто только предложил, спросил или пересказал —
  не decided_by. Нет явного согласия — decided_by: []. Реплики «Экран …» и «Речь на экране» — не согласие.

## Реплики и согласие (для переписки)

- Переписка — пронумерованные сообщения «M<номер> [дата время] Автор (в ответ на M<номер>): текст». decision/task/fact/
  open_question — только из сообщений основного текста; в messages — номера сообщений, где это прозвучало (например [106, 107]).
  Поле turns для переписки не заполняй.
- decided_by — кто из ДРУГИХ участников утвердил или явно согласился («да, делаем», «согласовано», «ок, берём»), с номером ЕГО
  сообщения: [{"name": "Иван Пример", "message": 112}]. Автор предложения не утверждает сам себя. Нет согласия — [].
- Блок «Уже разобрано в другой выгрузке» — только контекст: из него ничего не извлекай.

## Цитата и формулировка (для документов)

- Документ (не созвон и не переписка) дан пронумерованными единицами «P<номер> текст»: заголовок, абзац, пункт списка или строка
  таблицы. В каждом decision, task и open_question укажи paragraphs — номера единиц-источника (например [12, 13]) — и заполни
  quote — ДОСЛОВНУЮ цитату из этих единиц (одно предложение или строка, без пересказа и без «P<номер>», 12–300 знаков),
  из которой следует пункт. Код проверяет, что цитата есть в
  тексте; не нашёл — пункт уходит в «Не подтверждено источником». Не можешь привести цитату — не создавай пункт.
- Формулировка пункта строится по цитате. Не дописывай цель, причину или назначение («для возможности…», «чтобы…»),
  если их нет в тексте. Если действие уже совершено («сделал», «включил») и никто не просил повторять, это не задача
  и не решение: не создавай пункт.
