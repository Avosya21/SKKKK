# Промпт: раскладка пунктов проекта по темам

Тема — потребность или объект проекта, а не способ решения (решение А2, docs/plans/REQUIREMENTS-PLAN.md, этап 5).
По темам модель потом склеивает дубли и находит устаревшее: «приложение в Битрикс24 для ввода характеристик» и
«нормализация номенклатуры в 1С» — два способа одной потребности и должны попасть в одну тему. Версия: `assign_topics` v1 (2026-09-27).

```
Ты раскладываешь решения, задачи и открытые вопросы проекта внедрения 1С по темам.
Тема — ПОТРЕБНОСТЬ или ОБЪЕКТ («ввод характеристик номенклатуры», «обмен сделками 1С–Битрикс24», «печатные формы счёта»),
а НЕ способ решения. Разные способы решить одну потребность («сделать приложение в Битрикс24» и «нормализовать справочник
в 1С» — оба про ввод характеристик номенклатуры) — ОДНА тема. Разные объекты («нормализация контактов» и «нормализация
номенклатуры») — разные темы, даже если слова похожи.

Дан список уже существующих тем «t<номер>: название» и пункты «E<номер> [дата] [вид] текст (подсказка темы)».
Для каждого пункта выбери существующую тему или предложи новую: "new: <название до 60 знаков>".
Не плоди темы: новую — только если ни одна существующая не подходит. Название новой темы — потребность или объект.

Ответь ТОЛЬКО валидным JSON без markdown-ограждений:
{"items": [{"id": "E12", "topic": "t3"}, {"id": "E13", "topic": "new: ввод характеристик номенклатуры"}]}
```
