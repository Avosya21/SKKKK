# План: инструмент `projectmap` — полная карта любого проекта

**Статус:** согласован 2026-10-05, выполняется с 2026-10-05 (ход — в конце документа).
**Разрешение владельца (2026-10-05):** на установку и использование всего, что необходимо для реализации плана (пакеты, tree-sitter и грамматики, G6 и расширения, публичные образцы проектов). Разрешение действует только в рамках этого плана; личные данные и секреты в скачанное и в репозиторий не попадают.

## Цель

Инструмент `projectmap` строит карту любого проекта; SKKKK — первое применение. Новый проект подключается за три команды. Карта максимально полная: полнота измеряется охватом по слоям, а не ощущением.

## Определение полноты

Для каждого слоя считается доля «описано и связано / существует в проекте»; у каждого слоя целевой порог, отчёт охвата строит сам инструмент.

| Слой | Что входит |
|---|---|
| Структура | файлы, функции, классы, вызовы, импорты, наследование |
| Интерфейсы | роуты, кнопки и экраны, их связь с API |
| Данные | таблицы, столбцы, кто пишет и читает, миграции |
| Настройки | переменные окружения, конфиги, сервисы Docker, порты |
| Тесты | какие тесты покрывают какой код |
| История | коммиты, частота правок, пары файлов, меняющихся вместе |
| Смысл | описания, манифест, глоссарий, ссылки документ → код |
| Метрики | fan-in/out, группы (Louvain), «хабы», ключевые слова |
| Среда | процессы, скрипты запуска, внешние инструменты |

## Устройство

- **Ядро** `projectmap`: формат графа с версией, хранилище, метрики, проверки полноты. О SKKKK ничего не знает.
- **Парсер языков** на tree-sitter в ядре. Глубокий уровень (знание фреймворков): Python, JS/TS. Структурный уровень (символы, импорты, вызовы): Java, Kotlin, Go, C/C++, C#, Ruby, PHP, Swift, Rust, Groovy, Objective-C. Файловый уровень: всё остальное.
- **Адаптеры стека:** FastAPI, SQLAlchemy, Jinja, Docker, PowerShell, Markdown, git. Для нового стека — свой адаптер или конфиг.
- **Просмотрщик:** один самодостаточный HTML-файл, работает без интернета, светлая тема на токенах (тёмная — позже, без переписывания). Тот же компонент встраивается в страницу портала.
- **CLI:** `init`, `index`, `graph`, `check`, `export`, `serve`, `hooks`, `mcp`.
- **Данные** инструмента — в каталоге `.projectmap/` (не путать с `data/project_map.db` и `data/project_map_graph.json`; миграция — этап 7).

## Проверка общности без второго проекта

1. Эталонные мини-проекты по каждому языку и стеку (пишем сами, храним в тестах).
2. SKKKK как строгий потребитель: в коде ядра нет упоминаний SKKKK, `app/app` и имён наших таблиц — проверяет тест.
3. Тест «новый проект за три команды» на пустом эталонном проекте.
4. Публичные открытые проекты как контрольные образцы только на чтение (в рабочем каталоге вне репозитория; например, сам Emerge). Когда появится настоящий второй проект — прогон на нём без правки ядра.

## Этапы

**0. Рамки.** Зафиксировать цифры и скриншоты «до»; проверить чужие незакоммиченные правки индекса (`chunkers.py`, `search.py`, `store.py`, `indexer.py`); каркас `tools/projectmap` в этом репозитории (позже вынос в отдельный).

**1. Модель данных и аудит полноты.** Формальная схема графа и слоёв, отчёт охвата. На SKKKK найти, чего в карте нет совсем (предположительно: функции PowerShell, сервисы Docker, вызовы «скрипт → скрипт», миграции БД, ссылки документ → код), записать как задачи для адаптеров.

**2. Исправление данных и метрики.** Привязка вызовов по именам (подозрение: завышенный fan-in у `people.py` и `meeting_recordings.py` из-за общих имён `get`, `list_people`), Louvain на связях «вызывает» и «импортирует» без тестов, истории и манифеста (5 запусков, разрешение 1,5, нумерация групп по размеру, фиксированный seed), fan-in/out с порогами, частота правок, co-change, наследование классов, ключевые слова (TF-IDF по идентификаторам). Всё пишется в формат этапа 1.

**3. Многоязычный разбор и выделение ядра.** Проверить, что tree-sitter и грамматики ставятся в наше окружение (Windows, Python 3.10). Анализаторы SKKKK становятся адаптерами, пути и правила уходят в конфиг, добавляется структурный разбор остальных языков. Критерий: проходят эталонные проекты по всем языкам; тест «в ядре нет SKKKK» зелёный.

**4. Просмотрщик.** Пробная сборка G6 и Cytoscape по критериям: читаемость на 150 и 500 узлах, сворачивание групп, отклик на 2000+ узлах, упаковка в один офлайн-файл, токены светлой темы. Решение, затем реализация: группы со сворачиванием, оболочки, цвет по подсистеме и группе, размер по метрике, легенда, карточка узла, поиск с подсветкой, тепловая карта правок, панель общей статистики, шкала времени.

**5. Упаковка.** Пакет с CLI, `init` (определяет стек, создаёт конфиг и заготовку карты), универсальные git-хуки (карта и личные данные), MCP, README, пример «новый проект за три команды».

**6. Генерация заготовки карты.** По графу собирать скелет `PROJECT-MAP.md` (роуты, таблицы, настройки, модули); смысловые описания вписывает человек или ИИ, проверка полноты не даёт их пропустить.

**7. Внедрение в SKKKK.** Страница `/admin/map/graph` встраивает тот же просмотрщик; скрипты индекса становятся тонкими обёртками; данные переезжают в `.projectmap/`; поведение и тесты не теряются.

**8. Закрепление.** Карта (§16, §5), атлас, манифест; сверка `check_map_drift`, `check_stand_inventory`, `index_doctor`, тесты, живая проверка страницы, отчёт охвата по слоям.

## Правила работы

- Отдельный коммит на тему; коммитить только свои файлы и свои фрагменты общих файлов; хуки карты и личных данных не обходить.
- Скачивание и установка — в рамках разрешения владельца выше, с записью, что и откуда поставлено, и фиксацией версий.
- Идеи Emerge (MIT) и G6 (MIT) перенимаются, код Emerge не копируется; при заимствовании кода — указание авторства.
- Решения на этапах 3 и 4 (движок просмотрщика, состав языков) фиксируются в `docs/DECISIONS.md`.
