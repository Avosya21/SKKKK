## 2. Целевое устройство

1. Извлечение отдаёт **структурированный markdown**: блоки в порядке документа; таблица — GFM-таблица под своим заголовком раздела, с подписью `Таблица N: <раздел / имя листа>`.
2. Таблицы **не проходят через LLM-нормализацию**: LLM чистит только прозу, таблицы вставляются обратно дословно (цифры не трогаются).
3. Нарезка **понимает таблицы**: чанк = заголовок раздела + шапка таблицы + целые строки; большие таблицы режутся по строкам с повтором шапки в каждом чанке. Для широких/длинных таблиц дополнительно — строковое представление «Столбец: значение; …» (записи), чтобы одна строка была самодостаточной.
4. Поиск в чате **гибридный**: вектор + FTS5 по чанкам проекта, слияние RRF.

## 3. Шаги

### Шаг 1. Общий формат таблицы (`app/app/services/table_md.py`, новый)
- `Table` (caption, header: list[str], rows: list[list[str]], source: "docx|xlsx|pdf|csv", location: раздел/лист/страница).
- `render_md(table)`: экранирование `|` → `\|`, `\n` в ячейке → `<br>`, выравнивание числа столбцов, пустая шапка → `Столбец 1..N`, многоуровневая шапка склеивается через ` / `.
- `render_records(table)`: строки вида `Этап работ: Слой ИИ / MCP; Стоимость, руб.: 240 000`.
- Маркеры блока в тексте: `<!-- table:N -->` … `<!-- /table -->` — по ним нормализация и нарезка находят таблицы, не разбирая markdown эвристикой.
- **Проверка:** unit-тесты на экранирование, merged, пустую шапку.

### Шаг 2. DOCX в порядке документа (П2, П3)
- Обход `doc.element.body.iterchildren()`: `w:p` → абзац (стиль `Heading N` / `Заголовок N` → `#`×N; списки → `- `), `w:tbl` → таблица на своём месте, `w:sdt` → содержимое.
- Merged-ячейки: брать уникальные `cell._tc` по строке (горизонтальный merge — одна ячейка), вертикальный merge — значение повторяется (так строка остаётся самодостаточной).
- Вложенные таблицы — рекурсивно, отдельным блоком после родительской строки.
- Колонтитулы — один раз в начале (`## Колонтитулы`), только если отличаются от пустых; надписи (`w:txbxContent`) — как абзацы.
- `.doc` / `.rtf` со сложной вёрсткой → конвертация через LibreOffice (переиспользовать `pptx_extract._find_soffice`, вынести в `office_convert.py`) → `.docx`.
- **Проверка:** фикстура-docx (заголовки, таблица в середине, merge, `|` и перенос в ячейке, вложенная таблица) → ожидаемый markdown. Повторный прогон на art 3, 8: таблица стоит под «1. Общие сведения».

### Шаг 3. Excel / CSV (П1)
- Зависимость: `openpyxl` (xlsx/xlsm), `xlrd` не нужен — `.xls`/`.ods` конвертируются LibreOffice в `.xlsx`. Добавить в `app/requirements.txt`. **Новая зависимость — согласовать** (см. раздел 5).
- `upload.py`: `.xlsx .xlsm .xls .ods` → `file_type="xlsx"`; `.csv .tsv` → `file_type="xlsx"` (табличный путь), а не `txt`. `contract.py:127` — добавить `xlsx`.
- `xlsx_extract.py`: `load_workbook(read_only=True, data_only=True)` (значения формул, а не формулы), для каждого видимого листа — `## Лист: <имя>`; поиск используемой области (обрезать пустые хвосты), разбиение листа на несколько таблиц по пустым строкам/столбцам; строка шапки = первая непустая строка блока (эвристика: больше всего текстовых ячеек); merged-диапазоны (`ws.merged_cells`) разворачиваются значением; даты → `ДД.ММ.ГГГГ`, числа — без научной записи, с сохранением формата процента/денег где он задан. Скрытые листы — пропускать с пометкой в логе.
- Лимиты: `XLSX_MAX_ROWS_PER_SHEET` (напр. 5 000), `XLSX_MAX_CELLS` — сверх лимита лист сохраняется частично, в тексте явная пометка «показаны строки 1–5000 из N», в `log_event` — `xlsx.truncated`.
- CSV: `csv.Sniffer` для разделителя, кодировка через существующий `_decode_text_bytes`.
- `project.html:590` — `accept` со списком поддерживаемых расширений; для неподдерживаемого типа — внятная ошибка при загрузке, а не «no text extracted» в очереди.
- **Проверка:** фикстуры: смета с merged-шапкой и итогом по формуле, лист с двумя таблицами, скрытый лист, CSV с `;` в cp1251 → ожидаемый markdown.

### Шаг 4. Таблицы в PDF (П4)
- `fitz` (уже стоит, PyMuPDF 1.28): `page.find_tables()` → для каждой таблицы `extract()` → `Table`; текст страницы — без областей таблиц (`page.get_text("blocks")` с исключением `table.bbox`), чтобы не было дублей; порядок — по вертикали.
- Скан-страницы (OCR) — как сейчас, без таблиц (отдельной задачей при необходимости).
- **Проверка:** «Клиент Б. Смета. Планирование - Лист1.pdf» (art 17) → таблица «№ | Этап работ | Стоимость | Комментарий», итог в своей строке.

### Шаг 5. Нормализация без потерь (П5)
- `normalize_document`: вырезать таблицы по маркерам → в LLM уходят только прозаические куски с плейсхолдерами `[[TABLE_N]]` → вставить таблицы дословно обратно; если плейсхолдер пропал — дописать таблицу после предыдущего блока (не терять).
- `_split_sections`: при отсутствии `#` резать по абзацам до `max_chars` (сейчас не режет вовсе).
- Защита от обрезки: если `len(clean) < 0.7 × len(prose)` для куска — брать `light_normalize` этого куска, `log_event("normalize.shrunk")`.
- Для `xlsx` LLM-нормализацию не вызывать вообще (там только таблицы) — `light_normalize`.
- **Проверка:** тест с таблицей + прозой: цифры таблицы в `clean` байт-в-байт; тест на документ 60 000 символов без заголовков — в LLM ушло ≥ 6 частей (мок LLM).

### Шаг 6. Нарезка с учётом таблиц (П6)
- `chunk_document(text)` в `chunking.py`: сначала делим на блоки (заголовок раздела / проза / таблица по маркерам), прозу — как раньше, но без склейки переводов строк в пробел.
- Таблица, влезающая в `CHUNK_TOKENS`, — один чанк целиком: `контекст (документ › раздел / лист) + подпись + шапка + строки`.
- Большая таблица — окна по строкам, в каждом чанке повтор контекста и шапки, без перекрытия посреди строки.
- Широкая таблица (> ~8 столбцов или строка > 1/3 чанка) — чанки в виде записей `render_records` (каждая строка самодостаточна).
- Сохранить в `Chunk` признак `kind` (`text` / `table`) и `location` (лист/раздел/страница) — **миграция схемы `chunks`, согласовать** (или хранить в тексте шапки чанка, без миграции — вариант по умолчанию).
- `indexing.index_artifact`: для не-аудио вызывать `chunk_document`.
- **Проверка:** таблица на 300 строк → каждая часть начинается с шапки; ни одна строка не разрезана; сумма строк по чанкам = 300.

### Шаг 7. Гибридный поиск в чате (П7)
- FTS5-таблица `chunks_fts(text, content='chunks')` в `app.db` + триггеры на insert/delete (как в `project_index/store.py`), токенайзер `unicode61 remove_diacritics 2`.
- В поиске чата: top-K вектора + top-K FTS (запрос — слова вопроса ≥ 3 символов и все числа), слияние Reciprocal Rank Fusion, затем текущие `enrich_and_rerank_hits`.
- `_document_context_blocks`: вместо «первых 3 500 символов» — лучшие по FTS чанки этого документа.
- **Проверка:** «сколько стоит слой ИИ» по смете → в контексте чанк со строкой «Слой ИИ / MCP … 240 000» и шапкой.
