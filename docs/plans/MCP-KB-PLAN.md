## 1. Решения (владелец, 2026-10-08)

| # | Вопрос | Решение |
|---|---|---|
| В1 | Размер порции | По умолчанию **60 КБ** (≈ 20 тыс. токенов — помещается в лимит ответа инструмента Claude Code и Cursor); параметр `page_bytes` до 200 КБ. Контракт: «до 200 КБ, по умолчанию 60» |
| В2 | Память решений в режиме shadow | **Нет**: как и чату — только live; иначе ошибка `memory_not_live` |
| В3 | Лимит на чтение | **Нет**, только журнал `mcp.call`; лимит — если журнал покажет нужду |
| В4 | Отклонённые материалы | В списке с пометкой и причиной; содержимое не отдаётся |

Совместимость: поля и инструменты только добавляются; прежние вызовы отвечают как раньше (кроме размера порции). Агентам — письмо в `contract/letters/`.

## 2. Этапы

| Этап | Что | Проверка |
|---|---|---|
| Э0 | `scripts/mcp_audit.py <проект>`: размер каждого ответа, обрезка, пустоты, вид отданного содержимого (без самого содержимого); отчёт «до» по пяти проектам в `data/eval/` | отчёт есть |
| Э1 | `get_artifact_content`: источники по типу материала (созвон: summary, brief, outline, transcript; документ: summary, text; переписка: summary, text, messages), порции по строкам с курсором, `total_chars`/`offset`/`cursor`/`truncated`; `auto` — выжимка, иначе текст; отклонённый/неготовый — причина | стенограмма 300 тыс. символов читается порциями целиком; у документа и переписки текст не пустой; старые вызовы совместимы |
| Э2 | Порции у `list_entities`, `list_conflicts` (через `contract.paginate`), конфликты — разобранным JSON; `search_project` — текст до 800 символов, дата/автор где известны; общий страж размера в `call_tool` | на данных проекта 18 ни один ответ не больше порции |
| Э3 | Инструкция `initialize` по правам ключа; `mcp/info` без устаревших цифр; руководство 1.3; CONTRACT.md / POLICY.md | `test_agent_guide`, `test_project_mcp` |
| Э4 | Журнал `mcp.call`: проект, префикс ключа, инструмент, имена параметров, размер, время, ошибка — без содержимого; счётчик по ключам в сводке обмена | тест: вызов в журнале, содержимого нет |
| Э5 | `get_decisions`: предметы, лента с цитатами, состояние на дату, поиск; только live; логика экрана памяти — в сервис, общий для экрана и MCP | shadow — отказ; live — данные порциями |
| Э6 | Карта, «Исправлено», письмо агентам, перезапуск, живая проверка по HTTP ключом песочницы, аудит «после» | критерий ниже |

**Критерий готовности (отчёт `mcp_audit.py`):** ни один ответ не больше порции; ни одной молчаливой обрезки; у всех готовых документов и переписок есть текст; память решений отдаётся в live-проектах и отклоняется в остальных; инструкция совпадает с правами ключа; вызовы приёмки видны в журнале.
