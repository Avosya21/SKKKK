# SKKKK — Люди, компании, учётки и голоса: сквозной путь

Статус: **v1 (2026-10-16), решения Р1–Р6 приняты владельцем и записаны в `DECISIONS.md`; идёт ЛГ1–ЛГ2.** Продолжение [`PLATFORM-FOUNDATION-PLAN.md`](PLATFORM-FOUNDATION-PLAN.md): там построены реестр людей, стороны проекта, справочник компаний, «Кто это?» и согласие на голос (ПФ0–ПФ10). Каждая часть работает, но части не сцеплены между собой: компания и сторона вводятся в нескольких окнах по-разному, учётки, люди проектов и голоса связываются вручную или не связываются вовсе. Этот план сводит всё в один путь — от заведения проекта до расшифровки созвона.

## 0. Цель

После плана в портале:

1. Компания существует **один раз** — в справочнике; проекты, люди и карточки сотрудников ссылаются на неё, а не пишут название текстом.
2. Сторона (заказчик / исполнитель) задаётся **у компании в проекте**; человек получает сторону от своей компании и не может ей противоречить.
3. Сотрудник с учёткой — **всегда один и тот же человек** во всех проектах: участник проекта, участник встречи, говорящий в созвоне и автор в переписке связываются через учётку, а не по совпадению имени.
4. Голос **принадлежит** учётке (сотрудник) или человеку проекта (внешний, с согласием), а не просто имени.
5. В каждом материале проекта говорящие и авторы указывают на людей реестра; неопознанные — в «Кто это?», а не в выдуманных людях.

## 2. Модель: пять сущностей и одно правило на каждую

| Сущность | Где | Правило |
|---|---|---|
| **Компания** | `companies` (+ `Companies.txt`) | Заводится один раз; новая компания из любого окна попадает в справочник. Сторона компании в справочнике — только значение по умолчанию. |
| **Учётка** | `users` + `user_profiles` | Сотрудник = учётка с карточкой (ФИО, компания). Без карточки учётку нельзя сделать участником проекта. |
| **Сторона проекта** | `project_parties` (с `company_id`) | Единственное место, где задаётся сторона. Внутренний проект — только сторона исполнителя. |
| **Человек проекта** | `people` | Компания — только из сторон проекта; сторона = сторона компании в проекте (не правится у человека); учётка — если это сотрудник. |
| **Голос** | `speaker_profiles` | Принадлежит учётке (`user_id`, общий для всех проектов) или человеку проекта (`person_id`, только в проекте, с согласием — Д5). Голос без владельца — только «на разборе». |

Сторона «третьей» компании (подрядчик заказчика, партнёр) решается так же: компания добавляется в стороны проекта со своей стороной.

## 3. Сквозной путь

1. **Новый проект.** Заказчик выбирается из справочника (или «Новая компания» — сразу в справочник со стороной «заказчик»); исполнитель — по умолчанию компания автора; флажок «Внутренний проект» убирает заказчика. Получаются стороны проекта; автор — человек проекта; люди заказчика — по желанию, их компания уже выбрана.
2. **Участники.** Добавленный в проект сотрудник сразу становится человеком проекта: имя и компания из карточки, сторона — от компании.
3. **Встреча в комнате.** Вошедший по учётке — сразу человек проекта. Гость вводит имя; после встречи — совпадение с человеком проекта или «Кто это?». В стенограмме — каноническое имя человека.
4. **Загруженный созвон.** Карточки голосов: сначала люди проекта, затем сотрудники, затем «новый человек». Для нового — выбор компании только из сторон проекта; выбрал сторону — компания подставилась (если на стороне одна). Подтверждение привязывает голос к учётке (сотрудник с согласием в карточке) или к человеку (внешний с отметкой согласия).
5. **Переписка.** При загрузке выгрузки авторы сверяются с людьми проекта и учётками; незнакомый автор — «Кто это?» (людей сама не заводит).
6. **Документы.** Людей не дают (решение 2026-10-16); упомянутые имена остаются в тексте.
7. **Анализ и выжимка.** Имя, компания и сторона реплики берутся у человека реестра.

## 4. Решения владельца (нужны до старта)

| № | Вопрос | Рекомендация |
|---|---|---|
| Р1 | Сторона человека всегда равна стороне его компании в проекте, правка — только у компании? | Да. Расхождения сейчас — ошибки ввода (1 случай) |
| Р2 | Новая компания из формы проекта и из сторон проекта сразу попадает в общий справочник? | Да, со стороной по умолчанию по роли в проекте; убрать из справочника может админ |
| Р3 | Компания заказчика при создании проекта обязательна? | Да, кроме флажка «Внутренний проект» |
| Р4 | Платформа (`MEMORY_PLATFORM`) включена у новых проектов сразу? | Да; у старых — после того как заполнены стороны (ЛГ7) |
| Р5 | Голос сотрудника привязывается к его учётке сам при подтверждении карточки голоса, если согласие в карточке есть? | Да: подтверждение карточки и есть решение человека; отдельная кнопка остаётся для старых голосов |
| Р6 | Учётку без карточки нельзя добавить в проект? | Нельзя добавить без фамилии, имени и компании; форма добавления участника предлагает заполнить карточку |
| Р7 | Согласие на голос: подтверждённый голос из загруженного созвона и гость встречи сами становятся людьми проекта? | Да (решение владельца 2026-10-16): запись загружают только с согласия; гость соглашается при входе и указывает компанию |

Размер: S — до дня, M — 2–3 дня. После каждого этапа: тесты, `index_project_map.py`, `PROJECT-MAP.md`, `changelog.json` (если видно пользователю). Перед любой правкой данных — копия БД в `data/backups/`, сначала прогон без записи.

**ЛГ1. Единый справочник компаний (M).** Форма нового проекта и форма сторон проекта: выбор компании из справочника с пунктом «Новая компания»; новая — `companies.save_company` (файл и таблица) со стороной по роли (Р2); `people.set_party` всегда пишет `company_id`. Обязательный заказчик и флажок «Внутренний проект» (Р3). Скрипт сведения: 31 сторона без `company_id` (10 компаний вне справочника) — занести в справочник или связать с уже существующей компанией; слияние написаний одной компании (список на подтверждение владельцу). Тесты: создание проекта с новой и существующей компанией, внутренний проект, сведение написаний. Критерий: у всех сторон проектов есть `company_id`, одинаковых компаний под разными написаниями нет.

**ЛГ2. Сторона от компании (M).** Компания человека — только из сторон проекта (в форме человека — список сторон проекта и «Добавить компанию в проект»); сторона человека вычисляется из стороны компании и в форме не правится (Р1). Смена стороны компании в проекте меняет сторону всех её людей в проекте (одной записью журнала на каждого). Сведение данных по отчёту ЛГ0: 15 людей без компании, 18 «не знаем», 1 противоречие — список на решение владельцу, затем применение. Карточка голоса и страница разбора голосов используют тот же список компаний. Тесты: человек не может получить сторону против компании; смена стороны компании переносится на людей. Критерий: в БД нет людей со стороной ≠ стороне компании в проекте.

**ЛГ3. Учётки ↔ люди проекта (S).** `upsert_member` вызывает `people.person_from_user`: участник проекта сразу человек проекта; дозаполнение 22 участников без человека скриптом. Без карточки участника не добавить (Р6). Смена компании в карточке сотрудника переносится на его людей во всех проектах (если компания у человека пришла из карточки). Тесты: добавление участника, смена компании в карточке. Критерий: у каждого участника проекта есть человек с учёткой.

**ЛГ4. Голоса ↔ учётки и люди (M).** Подтверждение карточки голоса: человек с учёткой и согласием в карточке → голос получает `user_id` (Р5); внешний — `person_id` (как сейчас). Карточка голоса: компании только из сторон проекта, подстановка компании по стороне, люди проекта первыми. Старые голоса без владельца (75): страница разбора голосов (`scripts/voice_review.py`) показывает предложение владельца — учётка (по подтверждённым созвонам и карточке) или человек проекта — и применяет решение владельца. Тесты: подтверждение карточки сотрудника и внешнего; голос без согласия не привязывается. Критерий: у голосов с подтверждёнными созвонами владелец известен ≥ 90 %.

**ЛГ5. Комната (S–M).** Дозаполнение `meeting_participants.person_id` у завершённых встреч проектов с платформой (`link_meeting_participants` по старым встречам, копия БД, прогон без записи). Имя гостя в стенограмме комнаты приводится к каноническому имени человека (остаток ПФ7). Включение платформы у нового проекта (Р4). Тесты: связывание старой встречи, каноническое имя в стенограмме. Критерий: у участников завершённых встреч человек реестра ≥ 95 % (остальные — открытые «Кто это?»).

**ЛГ6. Переписка (S).** После разбора выгрузки переписки авторы сверяются с людьми проекта и учётками (`people.resolve`, карточки сотрудников); незнакомый автор — «Кто это?» (`chat_author`), людей сама не заводит. Тест на выгрузке с вымышленными авторами. Критерий: после загрузки переписки нет авторов без человека и без вопроса.

**ЛГ7. Старые проекты (S, работа с данными).** У 10 проектов без сторон: скрипт предлагает стороны (компании людей проекта и карточек участников), владелец подтверждает на странице «Люди и стороны»; затем включение платформы. Критерий: стороны есть у всех активных проектов.

**ЛГ8. Табло и приёмка (S).** Метрики на `/admin/memory` (по отчёту ЛГ0): доля сторон с `company_id`; люди со стороной от компании; участники проектов с человеком; голоса с владельцем; участники встреч с человеком; открытые «Кто это?». Приёмка — §6.
