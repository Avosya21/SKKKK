# Native-дорожки созвона: кто говорит и нужна ли диаризация

Дата: 2026-09-13. Рассуждения, не решение в DECISIONS. Код не менять, пока не выберем ветку.

## Как сейчас

Каждый участник пишет свою WAV (`voice_cleaner`). Имя берётся из LiveKit, не из модели.

На дорожке уже стоит `known_speaker.json` + `skip_sortformer`. `03_diar` **не** гоняет Sortformer: весь файл = `speaker_0` с вероятностью 1. Покраска красит все слова этим одним. Merge подписывает реплики именем из манифеста.

Итог: чужой голос в этот микрофон станет текстом **хозяина дорожки**. Страховки нет.

Покраска здесь не «узнать кто», а тот же контракт lab: слово → спикер → реплики → GigaAM/proof. На native-треке это почти no-op.

## Две разные беды

1. **Протечка.** Петя орёт, Дашин ноут это слышит. Две дорожки, один голос. Sortformer на Дашиной WAV может увидеть второго — или нет. Надёжнее смотреть **соседние дорожки в то же время**.
2. **Один микрофон на двоих.** Одна identity, два человека. Соседней дорожки нет. Тут Sortformer (или ручная пометка) уместен.

Не лечить оба одним и тем же.

## Ветки

### A. Доверять identity

Sortformer не включать. Покраска оставить как клей lab. Протечка = ошибка атрибуции. Норма, если гарнитуры и AEC держат.

### B. Страховка через соседние дорожки (предпочтительна для протечки)

Не диаризация «с нуля», а сверка треков:

- одно время, похожий текст / высокая корреляция → слово оставить на более громкой/своей дорожке, с чужой снять или пометить;
- в лаб-UI: «похоже, это голос с дорожки Пети».

Имена по-прежнему из LiveKit. GPU Sortformer не нужен. Нужен merge, который видит все треки сразу (сейчас merge только сдвигает и склеивает).

### C. Sortformer только по тревоге

Дешёвый триггер: длинная речь, пока соседняя дорожка тоже говорит то же; или явный второй кластер. Тогда Sortformer на **этой** дорожке. Иначе native как сейчас.

Риск: на чистой односпикерной WAV Sortformer выдумывает speaker_1 на шуме.

### D. Sortformer на каждой дорожке

Дорого, шумно, имена всё равно не даёт (`--no-voice`). `speaker_1` на треке Даши без сверки с Петей бесполезен. Не брать как default.

## Что не трогать

- Обычный файл (не созвон): Sortformer → покраска → sense. Это другой вход.
- Имя на native-треке не угадывать LLM.
- Не возвращать тройной ASR.

## Если делать — маленький шаг

1. В лаб встречи явно писать: «диаризация пропущена, имя из LiveKit».
2. На merge: найти перекрытия реплик с похожим текстом между дорожками — только метрика/флаг, без выкидывания слов.
3. По живым созвонам решить: хватает флага (ветка A+наблюдение) или нужен выкидыватель (ветка B).
4. Sortformer на native — только если увидим кейс «двое в один ноут» (ветка C), не заранее.

## Открытый выбор

- Протечка: A (смириться) или B (сверять треки)?
- Двое в один микрофон: игнорировать или C по тревоге?
- Покраску на native оставить (клей) или срезать до «все слова = известное имя»?
