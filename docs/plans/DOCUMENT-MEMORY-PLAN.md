# Документы в памяти решений

Решение владельца — 2026-10-09 (`docs/DECISIONS.md`, «Документы в памяти решений»). Продолжение `DECISION-MEMORY-PLAN.md` и `DECISION-MEMORY-STAGES-6-8.md` (Э8: «новый материал — созвон, выгрузка чата, документ — дописывается в память сам»; документ до сих пор не дописывался).

## 1. Проблема

Память решений строится из речевых актов реплик. У документа реплик нет, поэтому ТЗ, договоры, планы и таблицы задач в память не попадали (`memory_for_review`: `units=0`). Последствия:
- требование из ТЗ не становится предметом: если его потом изменили на созвоне, память видит только изменение, без исходного варианта;
- статус работ из плана или дашборда («Готово», «ждём заказчика») в журнал не попадает;
- чат и MCP по памяти решений не видят документов.

Статус документа по шапке не определить: на 2026-10-09 явных грифов «Утверждаю», «Согласовано», листа согласования нет ни в одном из 36 документов; подписи — в 3, версия — в 7, протоколы — 6. Владелец: «смотреть надо внутри документа, что там именно; иногда этого никто не знает».

## 2. Метод

1. **Единицы.** Абзац, пункт списка, строка таблицы (`doc_units.split_units`, адрес `P<n>`). Заголовок — «раздел» для следующих единиц, первая строка таблицы — шапка для строк (`doc_memory.document_units`). Ссылка «открыть в материале» уже ведёт к цитате в документе.
2. **Паспорт** (`doc_memory.passport`, промпт `document_passport.md`). По началу и концу текста: вид, сторона-автор, утверждён ли и кем, дата. На каждое поле — дословная цитата, код её проверяет; не подтверждено — «не известно». Файл `parsed/…/<artifact_id>_passport.json`, пересчёт при смене текста или версии промпта.
3. **Акты единиц** (промпт `speech_acts_doc.md`): `documented` (зафиксировано требование, решение, срок, цена, состав работ), `proposed`, `agreed`, `rejected`, `done`, `deferred`, `cancelled`, `blocked`, `asked`, `info`. Описание «как есть» без требования, оглавление, реквизиты — пропуск. Примечание в ячейке — свой акт. Цитата дословная, проверяет код. Сторона и дата акта — из паспорта, не от модели.
4. **Состояние «в документе»** (`documented`, `decision_log.fold`): записано, не подтверждено. Принимает согласие заказчика или другой стороны; отклоняет отказ; согласованное и выполненное не понижает; после отказа или снятия новый документ снова фиксирует. Документ, утверждённый заказчиком или обеими сторонами (по паспорту), — пункты сразу «согласовано».
5. **Судья** только там, где есть что решать (`subject_judge.needs_judge`): документ встретился с репликой, документов несколько или один документ говорит о предмете разное. Проверка готовности проекта считает долю итогов по тому же правилу.
6. **Сравнение с прежним контуром** находит акт пункта документа по `source_paragraph` — пункты документов теперь сравниваются, это мера качества.

Проверочного второго прохода, как у реплик (`speech_acts_review.md`), у документа в v1 нет: у пункта документа нет реакции на чужую реплику. Если на обкатке точность ниже порога — второй проход документа (Э4).
