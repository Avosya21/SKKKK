# projectmap

Карта любого проекта: граф файлов, функций, вызовов, интерфейсов, данных, настроек, тестов и истории правок, метрики
(группы Louvain, fan-in/out, частота правок) и **проверка полноты** — какая доля проекта описана и связана в карте.

**Статус:** этапы 1–4 плана `docs/plans/PROJECTMAP-PLAN.md`. Реализованы `version`, `index`, `graph`, `check`, `export`, `serve`; остальные (`init`, `hooks`, `mcp`) объявлены и сообщают, на каком этапе появятся.

## Для чего

Новый проект должен подключаться к построению карты за три команды:

```
projectmap init     # определить стек, создать конфиг и заготовку карты
projectmap index    # разобрать проект и построить граф
projectmap check    # сверить карту с проектом и показать охват по слоям
```

## Устройство

- **Ядро** — формат графа, хранилище, метрики, проверки полноты. Не знает ни одного конкретного проекта: проверяется тестом.
- **Парсер языков** (tree-sitter) — символы, импорты, вызовы для многих языков.
- **Адаптеры стека** — знание фреймворков (веб-роутеры, ORM, шаблоны, Docker, оболочки, документы, git).
- **Просмотрщик** — один самодостаточный HTML-файл без интернета.

## Просмотрщик (`projectmap export`, `projectmap serve`)

`projectmap export` выгружает карту: `--format html` (по умолчанию) — **одна страница без интернета** (библиотека G6 и данные внутри),
`json` — данные просмотрщика, `graphml` и `dot` — для Gephi, yEd и Graphviz. Результат по умолчанию — `.projectmap/out/map.<формат>`.
`projectmap serve` собирает страницу и открывает её в браузере (`--port`, `--no-open`). Название проекта на странице — `title` в конфиге.

Раскладка посчитана заранее (`layout.py`): подсистемы — круги, связанные ставятся ближе, внутри — силовая раскладка, узлы без связей — кольцом.
В странице: подсистемы со сворачиванием (двойной щелчок по оболочке; «Свернуть группы» показывает связи между подсистемами), цвет по подсистеме,
группе связности или тепловой карте правок, размер по fan-in, fan-out или правкам, легенда с фильтром по клику, поиск с подсветкой,
карточка файла (метрики, роуты, таблицы, переменные, тесты, документы, соседи), вкладка «Сводка» и шкала времени (правки за выбранный период, воспроизведение).

## Охват карты (`projectmap check`)

Для каждого слоя карты (структура, интерфейсы, данные, настройки, тесты, история, смысл, метрики, среда) пробы независимо от графа
находят, что есть в проекте, и считают, сколько из этого есть в графе. Цели и осознанные исключения — в `.projectmap/config.yaml`:

```
graph: путь к графу (json)
ignore: [маски путей, которые карте не нужны, — каждая с причиной в комментарии]
targets: {проба: минимальная доля охвата}
```

`projectmap check --format text|markdown|json`, `--only <проба>`, `--strict` (код выхода 1, если охват ниже цели).
Пробы: файлы, функции скриптов, сервисы compose, запуски «скрипт → скрипт», ссылки документов, интерфейс ↔ API, таблицы,
переменные окружения, тесты, история, метрики.

## Языки и грамматики

Python разбирается стандартным `ast`. Остальные языки — через tree-sitter (`tree-sitter`, `tree-sitter-language-pack`): Java, Kotlin, Go,
Rust, C, C++, C#, Ruby, PHP, Swift, Groovy, Objective-C, Scala, Dart, Lua, Shell, PowerShell, JavaScript и TypeScript. Грамматики скачиваются один раз
в `.projectmap/grammars` (не в git), дальше разбор идёт без интернета. Язык без грамматики остаётся на файловом уровне.

### Что разбор даёт по языкам

`s` — символы, `c` — вызовы, `i` — импорты, `b` — базовые классы и интерфейсы (список `CAPABILITIES` в `lang_specs.py`):
`scib` — JavaScript, TypeScript, TSX, Java, Rust, C#, C++, Ruby, PHP, Swift, Scala, Kotlin, Objective-C, Python; `sci` — Go, C, Lua, Shell, PowerShell;
`sib` — Dart (в дереве нет узлов вызовов) и Groovy (грамматика непригодна, разбор по регулярным выражениям). Замыкания принадлежат объемлющей функции
и своих символов не получают. Пределы: у Kotlin грамматика не разбирает `object` и `interface` с методами, у PowerShell — команды вида `Verb-Noun` в начале
строки внутри функций (имена функций и вызовы на уровне файла находятся).

## Адаптеры стека

Знание фреймворков и среды поверх разбора кода; каждый сам определяет, есть ли его стек в проекте (`adapters: auto`), или перечисляются в конфиге:
`fastapi` (роуты, обработчики, зависимости, проверки прав), `sqlalchemy` (таблицы, столбцы, кто читает и пишет), `env` (переменные окружения и образцы
`.env.example`), `docker` (сервисы compose), `markdown` (ссылки документов на файлы), `scripts` (запуски скриптов друг другом), `web` (экран → API,
шаблоны, которые отдаёт сервер, тесты, ходящие в роуты). Системные переменные ОС и перечисленные в `ignore_env` в проверках образца не участвуют.

## Запуск из репозитория

```
venv\Scripts\python.exe -m pytest tools/projectmap/tests -n 0
venv\Scripts\python.exe scripts\projectmap.py check
venv\Scripts\python.exe scripts\projectmap.py report    # документ docs/project-map/COVERAGE.md
```
